## B. ComfyUI install, launch flags, env vars (Strix Halo, 96 GB VRAM / 32 GB RAM)

**Install / update.** Use ComfyUI master at or after commit 6f3895e (2026-09-09, PR #16199) rather than the v0.35.0 tag: v0.35.0 `main.py:114` still sets `OCL_SET_SVM_SIZE='262144'` (256 GiB VA quota) and overwrites any value you export; master sets 4 TiB (`4194304`), which prevents the `access violation reading 0x...E0` VBAR crashes under DynamicVRAM (https://github.com/Comfy-Org/ComfyUI/pull/16199). If you stay on v0.35.0, edit that line to `'4194304'`. Then:
```powershell
pip freeze | Select-String "^(torch|torchvision|torchaudio|rocm|amd-torch|amd_torch|pytorch_triton_rocm|triton)" | Out-File -Encoding utf8 torch-pin.txt
pip install -c torch-pin.txt -r ComfyUI\requirements.txt      # pulls comfy-kitchen==0.2.33, comfy-aimdo==0.5.3 (Windows HIP kernels included in the PyPI wheel; no source build)
pip install --force-reinstall --no-deps comfy-aimdo==0.5.3      # only if startup raises 'get_simple_vram_headroom' (comfy-aimdo #112)
```
Always pass `-c torch-pin.txt` when installing custom-node requirements (that is where a PyPI torch pin drags in the CPU wheel).

**Launch (replace the arg block in `scripts\run_comfyui.ps1`):**
```
python main.py --listen 127.0.0.1 --port 8188 --highvram --bf16-vae --disable-pinned-memory --reserve-vram 4 --output-directory ..\output --disable-auto-launch
```
Why each: `--highvram` keeps the ~54 GB int8 set resident and avoids offloading a 27 GB TE into 32 GB host RAM; it also disables DynamicVRAM (needed on ROCm ≥ 7.14 stacks where gfx1151/Windows crashes are open: https://github.com/Comfy-Org/ComfyUI/issues/16102 , /15963). `--bf16-vae` (kyuz0, R9700 patch, uncompiled.tools all use it). `--disable-pinned-memory` (default pins ~13 GB of the 32 GB host). `--reserve-vram 4` (desktop + ComfyUI's ~12 GiB VRAM over-report: it prints "Total VRAM 110457 MB" for a 96 GiB carve-out). Drop `--bf16-unet` (redundant: MiniMaxH3 `supported_inference_dtypes=[bf16, fp32]`) and `--use-pytorch-cross-attention` (auto-detected; forcing bypasses the PR #15648 aotriton launch probe).

Do NOT add by default: `--disable-smart-memory` (offloads into host RAM; diagnostic only), `--disable-mmap` (with legacy loader it copies every tensor into anonymous host RAM; the Linux 300x mmap regression #6530 was retracted by its author), `--enable-triton-backend` (no win_amd64 ROCm Triton exists), `--supports-fp8-compute`, `--use-split/--use-quad-cross-attention` (suppress AMD auto-detect), `--gpu-only` for graphs that need CPU fallbacks.

Diagnostics to add one at a time: `--disable-smart-memory` (H3 noise/NaN mitigation #15314; Windows-AMD VAE "CUDA error: invalid argument", HF discussion #17), `--disable-async-offload` (libhipblaslt access violation during text encode, #15963), `--disable-cuda-graphs` (AMD corruption with graph capture, PR #16180), `--disable-dynamic-vram` (no-op on 7.13; required on ≥7.14 if you drop `--highvram`), `--force-fp32` for VAE decode isolation.

**Attention:** verify log shows `Using pytorch attention` (not `Using sub quadratic optimization` / `Could not run flash attention, disabling it`). Then A/B `--use-ck-attention` (mutually exclusive with the pytorch flag) or, preferred, the `ModelAttentionBackend` node = "comfy kitchen attention" per workflow; log should say `Using Comfy Kitchen attention`. HIP INT8 attention has been confirmed on Radeon 8060S/Windows with ~2x sampler speedup (35 min → ~4 min with 8-step LoRA): https://github.com/Comfy-Org/comfy-kitchen/issues/110 . Global flag is known to corrupt TRELLIS.2 (#16027), hence per-workflow node.

**Env vars (set in the launcher):**
- `TORCH_ROCM_AOTRITON_ENABLE_EXPERIMENTAL=1` — main.py sets it; set it yourself if any wrapper imports torch first (without it `can_use_flash_attention()` is False on gfx1151).
- `HIP_VISIBLE_DEVICES=0`, remove `CUDA_VISIBLE_DEVICES` (existing script already does).
- `MIOPEN_FIND_MODE=FAST`, `TORCHINDUCTOR_CACHE_DIR=C:\firemio\generate-local-H3\.inductor_cache` — optional.
- Do NOT set `PYTORCH_HIP_ALLOC_CONF=expandable_segments:True` on this box (local probe: OOM at ~14 GB). `HIP_FORCE_DEV_KERNARG=1` is a no-op on Windows (PAL runtime already defaults to device kernargs). `OCL_SET_SVM_SIZE` is overwritten by main.py (see above).
- `COMFY_KITCHEN_DISABLE_HIP=1` — diagnostic only, forces eager int8 (slow).

**64 GiB single-allocation cap:** with a 96 GB carve-out, HIP on Windows may still clamp any single allocation to 64 GiB and spill to shared memory (AMD fix rocm-systems PR #10974 merged 2026-09-04 to develop, not in any shipped Windows build; https://github.com/ROCm/rocm-systems/pull/10974 ; ROCm/ROCm #5940). Test: `torch.empty(70*2**30, dtype=torch.uint8, device='cuda')` and watch Task Manager Dedicated vs Shared. None of the recommended H3 files exceed 40 GB, so this only bites the bf16 TE (51.5 GB).

## D. Headless API graphs (POST /prompt {"prompt": {...}, "client_id": ...})

Common rules (from `comfy_extras/nodes_minimax_h3.py`, identical locally): `length` on the 17k+5 grid — `n=max(5,round(sec*24)); n += (5-n%17)%17` (5 s → 124, 10 s → 243, cap 362 ≈ 15.08 s; 328 is matsuo's safe production cap on 24 GB cards — irrelevant here but a per-step "cliff" appeared at 345 f); width/height multiples of 32, native 1344×768 (16:9), 768×1344, 768×768, 1024×768; smoke-test at 864×480 (template default). Poll: use `/ws?clientId=` events; never hit `/history` in a tight loop (stalls sampling 18-43 s); if polling, ≥45 s interval, 4 s timeout.

## E. Speed-ups that apply on AMD (in order of payoff)

1. **comfy-kitchen HIP INT8 attention** (`ModelAttentionBackend` / `--use-ck-attention`): ~2x sampler on gfx1151/Windows (comfy-kitchen #110); HIP int8 Sol-Attn (#143/#158, in 0.2.33) is compile-verified for gfx11 but run-verified only on RDNA4 — try, fall back to int8 attention/pytorch if noise on long clips (#140).
2. **Turbo LoRAs**: ~2.2x end-to-end vs 20 steps (matsuo: 339→154 s; 270→125 s on 5090). 4-step turbo ≈ same as 8-step (118 vs 125 s) because TE/VAE time is fixed.
3. **FastH3 4-step (fl2va/t2va only)**: use the ComfyUI-native, AdaLN-refitted `drozbay/MiniMax-H3-FastH3-Preview-LoRA` rank-128 file (1.33 GB; euler, simple, 4 steps, cfg 1, shift 12/3, pruned bases only): https://huggingface.co/drozbay/MiniMax-H3-FastH3-Preview-LoRA . matsuo's converted dense LoRA gave 1.87x over Turbo-8 with identity intact, but v1-derived conversions drop AdaLN (unusable at 4 steps, use 6). FastH3 VSA variants / full checkpoints / Sage / KJ PatchSageAttention / Triton / FeatherOps: CUDA-only or unavailable on Windows ROCm — skip.
4. **1216×704 instead of 1280×704** cuts VAE-decode tiles 28→24 (~-15% total).
5. **No HTTP polling during sampling** (websocket events); group jobs by checkpoint kind (fl2va vs ref2va) — with 96 GB both 21 GB DiTs may stay resident, so measure before caring.
6. **DiT-only tokens rule**: tokens = (((frames-5)//17)*5+2) × (W/32) × (H/32); 1344×768×124f ≈ 37k tokens; attention cost ≈ quadratic — 15 s clips at 768p are ~7x the 5 s cost.

Expectation calibration (the only gfx1151 numbers that exist): 1344×768×124f, 20 steps ≈ 2100 s (~35 min) on Windows/8060S with torch 2.12+rocm10.1 nightly, HIP int8 GEMM, attention unknown (comfy-kitchen PR #130, single run); Linux 480p×5 s: 88.7 s/it at 20 steps, 69.7 s/it at 8 steps (HF #33). Projected with Turbo-8 ≈ 16 min, plus ck attention ≈ 8 min, plus FastH3-4 ≈ 4-5 min per 5 s 768p clip. Real-time generation is not reachable; plan a buffer (Section F).

## F. AI TV station — minimal local stack

Fork https://github.com/reactor-team/infinite-livestream (Apache-2.0; chat Director → fail-closed moderation → LLM prompt-upsampler → generation queue + playout queue with idle filler → Pacer → ffmpeg RTMP sink) or https://github.com/shuttie/SlopTV (already an H3 FL2VA API graph on your exact int8 files; `generate.py` pool writer + `stream.py` single long-lived encoder). Replace the GPU backend with a ComfyUI-API worker.

```
[LM Studio gpt-oss-120b / Ollama gemma4]  --OpenAI-compatible JSON-->  director.py
   {title, scenes:[{id, kind:t2v|i2v|r2v, prompt(<d>[Japanese]…</d>), duration_s, refs}]}
        |
   queue service (FastAPI): GET /api/segment/claim (204 empty) · POST /progress (lease) · POST /result (mp4)
        |  worker claims only when its local ComfyUI queue is empty; same-kind jobs first
   worker.py -> ComfyUI :8188 (POST /prompt, /ws events)  -> pool/NNNN.mp4 (+ .json sidecar)
        |
   ffmpeg drawtext/ASS overlay for exact Japanese captions (optional)
        |
   MediaMTX (RTMP in -> HLS/WebRTC out) or ffmpeg HLS:
   ffmpeg -re -f concat -safe 0 -i playlist.txt -c:v libx264 -preset veryfast -c:a aac -ar 32000 -f hls -hls_time 6 -hls_list_size 10 -hls_flags delete_segments+append_list+omit_endlist out.m3u8
        |
   hls.js page (self-hosted; Twitch/Kick/Rumble removed the fal H3 stream within ~2.5 h)
```
Design rules: buffer math — with clip length L and measured generation time G, a show of length D drains the buffer by D·(1-L/G); at G/L≈10 (Turbo-8 + ck at 768p) a 4 h show needs ~3.6 h pre-rendered, so pre-render whole program blocks. ## G. Known pitfalls (this stack)

1. ComfyUI prints "Total VRAM 110457 MB" for a 96 GiB carve-out; VRAM+RAM budget (142 GB) exceeds physical 128 GB — subtract ~12 GiB mentally; HIGH_VRAM is never auto-selected.
2. Single HIP allocation > 64 GiB may spill to shared memory on Windows (fix not shipped). Keep every file ≤ 40 GB.
3. `expandable_segments` OOMs at ~14 GB on this box (local probe). Leave allocator default.
4. DynamicVRAM (ROCm ≥ 7.14 stacks) → `vbar_allocate` access violations on gfx1151/Windows (#16102, #15963, open). `--highvram` sidesteps it; else `--disable-dynamic-vram`; ensure main.py's 4 TiB `OCL_SET_SVM_SIZE`.
5. Noise/mosaic/black output = weight-reload corruption on rocm7.15-alpha/torch 2.13(+rocm7.2) builds (#15314, open); `--disable-smart-memory` dropped failures 40%→0; NaNs land in VAE weights — check VAE, try `--force-fp32` decode / Tiny VAE; switch DiT to bf16 to isolate int8 path.
6. I2V/Ref2V SIGSEGV in Qwen3-VL vision Conv2d on ROCm (#15895, Linux, open) — T2V first.
7. `--use-ck-attention` exits ComfyUI if HIP int8 attention is unavailable; "4-element alignment" error = stale comfy-kitchen < 0.2.31; pure noise on long/high-res clips (#140) → back to pytorch attention for that graph.
8. UnicodeDecodeError / "Unknown quantization format" on comfy_quant tensors (#15400, PR #15410 still open) → re-download and hash-check the file.
9. Windows-AMD VAE "CUDA error: invalid argument" (HF #17) → `--disable-smart-memory` for that run.
10. `pip install` never with `--pre`, never `rocm[...]` + torch in one command (resolver loops, TheRock #2849); spaces in path break rocm-sdk CLI wrappers on 10.0.0 stable.
11. Windows PyPI comfy-kitchen HIP `.pyd` is ROCm-7.2.1-built; if `list_backends()` shows hip unavailable after a torch change, source-build with `COMFY_KITCHEN_BUILD_HIP=1 COMFY_HIP_ARCHS=gfx1151` (VS2022 v143, CMake ≥ 3.26, Ninja).
12. matsuo found 345-frame clips randomly 3-17x slower on 24 GB; keep ≤ 328 f until measured here.
13. Japanese kana in-frame corrupt deterministically; kanji or post overlay.
14. Motion-Context and Director packs: "queue run on change" walks indices wrong; ROCm untested by their authors; AIMixer Director passes width/height as strings on Windows (#111) — pull latest.
15. Templates default to 864×480 (t2v/r2v) and 640×640 (i2v); ResolutionSelector megapixels 0.98 = 1344×768, 1.0 = 1376×768 (over cap).
