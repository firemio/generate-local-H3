# AIテレビ局 (aitv)

「ローカル LLM が番組を書き、MiniMax H3 が映像と音声（日本語のセリフ込み）を生成し、
ブラウザ／HLS で流し続ける」放送局。局は **Go の単一バイナリ**（`bin\aitv.exe`、`cmd/aitv` + `internal/*`）。生成は完全ローカル。ネットワークは**素材の読み取りだけ**
（気象庁の予報 JSON と NHK の RSS 見出し。どちらも API キー不要）。

```
   気象庁 forecast JSON ─┐                                 ┌──────────────────────┐
   NHK RSS (主要/科学/スポーツ)┴▶ internal/sources ─ 素材 ─────▶ │  internal/producer    │
             ┌───────────────┐   番組表(重み付き乱択)      │  LLM(Ollama/LM Studio)│─┐ H3 プロンプト(JSON)
             │ internal/     │ ──────────────────────────▶ │  → internal/comfy     │ │
             │  programs     │                             │  → ffmpeg normalize   │◀┘
             │  variety/..   │                             └──────────┬───────────┘
             └───────────────┘                                        │
                                                                   aitv/library/*.mp4 + index.json
                                     ┌─────────────────────────────┼──────────────────────────┐
                                     ▼                             ▼                          ▼
                            internal/server (:8800)         internal/hls (ffmpeg)          任意の再生ソフト
                            /            プレイヤー           aitv/hls/live.m3u8         VLC / OBS で視聴
                            /playlist.json                    (連続ライブ配信)
                            /clips/<file>
```

## 使い方

```powershell
# 1. ComfyUI を起動（別ターミナル）
.\scripts\run_comfyui.ps1
# 2. ローカル LLM（どちらか）
ollama serve            # gemma4:latest を既定で使用
# LM Studio なら: サーバを起動して --llm-url http://127.0.0.1:1234/v1 --llm-model <model>
# 3. 局をビルド（Go 1.26+、初回だけ）して起動: Web プレイヤー + HLS + 制作ループ
.\scripts\build.ps1
.\bin\aitv.exe station --port 8800
# → http://127.0.0.1:8800/  （HLS: http://127.0.0.1:8800/hls/live.m3u8）
```

個別に:

```powershell
.\bin\aitv.exe produce --count 1 --formats nature --minutes 2   # 2分の自然番組を1本だけ制作（動作確認向け）
.\bin\aitv.exe serve                                             # プレイヤーだけ
.\bin\aitv.exe hls                                               # HLS 配信だけ
.\bin\aitv.exe renorm [--dry-run]                                # 既存ライブラリの音量を基準に揃える（音声だけ再エンコード、約1秒/本）
```

### 音量（`internal/loudness`）

H3 の生成音声は素のままだと -30〜-10 LUFS とクリップごとに 20 dB 近くばらつく（ささやくナレーターの直後に
叫ぶ局 ID）。ライブラリに入れるとき ffmpeg の **2 パス loudnorm** で全クリップを **-16 LUFS / -1.5 dBTP**
（配信サービスの標準。ARIB TR-B32 の -24 LKFS はブラウザ再生には静かすぎる）に揃える。1 パス目で実測し、
2 パス目は可能な限り一定ゲイン（linear）で補正、ピークが当たるときだけリミッター。実質無音（-50 LUFS 未満）は触らない。
基準は `AITV_LUFS` で変えられる。以前に作ったクリップは `aitv renorm` で揃える（放送中でも可。
配信中のクリップはロックされているので飛ばされる → 後でもう一度実行。基準 ±1 LU 以内のものは触らないので何度実行しても同じ）。

## 1 日の編成と番組フォーマット（`internal/programs`）

1 日 = `LINEUP` の 8 枠。制作ループはこの順に番組を作り続け（1 周 ≈ 1 日）、放送もこの順に回る。
翌日には各枠が新しい番組に置き換わっている、というリズム。

| 枠 | key | 番組 | 尺 | 素材 | 内容 |
|---|---|---|---|---|---|
| 1 | news | ニュース | 6 分 | NHK 見出し（主要・社会・経済・国際・スポーツ・科学文化） | 1 人のアンカーがカテゴリ順に**実際の見出し**を読む。映像は人物・ロゴを出さない象徴的な風景 |
| 2 | weather | お天気 | 4 分 | 気象庁予報（今日・明日・週間、気温、降水確率） | 指定地域（既定 130000=東京）の予報と生活アドバイス |
| 3 | variety | バラエティー | 6 分 | NHK スポーツ・科学文化 | 2 人の司会＋ゲスト。今日の話題でトーク、クイズ、ゲーム |
| 4 | music_show | ミュージックステージ | 6 分 | – | 司会＋架空アーティスト 3 組のライブ |
| 5 | nature | 自然ドキュメンタリー | 6 分 | – | 1 つの生態系を「一日」として描く。ナレーション 1 人 |
| 6 | cooking | 3分クッキング | 5 分 | – | 1 品を材料から盛り付けまで |
| 7 | travel | ぶらり旅 | 6 分 | – | 架空の町をリポーターが歩く（実在の地名・名所は出さない） |
| 8 | news | ニュース（夜） | 6 分 | NHK 見出し | 朝の枠と同じ作り。素材が更新されているので内容が変わる |

合計 45 分/日。640×352 で 1 分の映像に約 30 分の GPU 時間がかかるので、これで GPU がほぼ一日中埋まる。
番組と番組の間に流す CM / 局 ID は、各番組の後に 1 本ずつ交互に作り足す（4〜6 秒なので安い）。

`--minutes N` で全番組の尺を揃えて上書きできる（`run_station.ps1 -Minutes 3` など。短いほど 1 日の周回が速い）。

### 台本（`internal/script`）

番組は LLM が **2 段階**で書く:

1. **構成表**: タイトル、レギュラー出演者（役割・名前・外見・声。外見と声は英語で 1 文、以後すべてのカットにそのまま貼られる）、
   コーナー（名前・秒数・進行）。オープニングとエンディングを含む 4〜7 コーナー、秒数は尺に合わせて正規化。
2. **コーナーごとの台本**: 6〜10 秒のクリップ列（caption / seconds / H3 プロンプト）。前のカットの終わりを渡して続きを書かせる。

LLM には H3 公式のプロンプト構造（`integrated_multimodal_description` / `overall_soundscape` /
`non_diegetic_music`、セリフは `<d>[Japanese] …</d>`、話者は `(S1)`）を system prompt で教える。
書き上がった台本は `aitv/library/scripts/<番組ID>.json` に丸ごと残る（構成表・出演者・全カットのプロンプト）。
次の番組の台本は、今の番組のレンダリング中に CPU で先に書く。

**日々変わる・続く（`script.History` / `programs.Themes`）**: 構成表を書くときに、同じ番組の直近エピソード
（タイトル・テーマ・あらすじ・次回予告）を渡して「同じ題材は避ける、前回の引きがあれば受ける」と指示する。
出演者は `regular: true` の人物（司会・ナレーター・シェフ・リポーター）を前回からそのまま引き継ぎ、ゲストや
出演アーティストは毎回変わる。各エピソードは「次回予告」を 1 行残し、次の回の冒頭素材になる（旅なら次の行き先、
料理なら次の一品）。題材は生態系・料理ジャンル・町の種類・音楽ジャンル・ゲーム種目のリストから
「最近使っていないもの」を提示して回す。ニュースは直近 36 時間に読んだ見出しを渡し、続報がなければ繰り返さない。
CM も直近の商品名を渡して別のものを作らせる。
制作は約 27 時間周期でずれていくので、朝と夜のニュース枠が同じ時間帯に重なることがある。直前のニュースから
5 時間（`min_gap_hours`）経っていなければ素材が同じなので、その枠は飛ばして次の番組へ進む。

**読み（`internal/yomi`）**: H3 は漢字の読みを文脈から推測するので、異読の取り違え（火加減→かかげん）が
聞こえる程度に起きる。台本は自然な漢字かな交じりのまま保存し、**レンダリング直前に `<d>[Japanese] …</d>` の中だけを
ひらがなに変換**して H3 に渡す（形態素解析 kagome + IPA 辞書。ひらがな・カタカナ・英数は無変換、は/へ/を もそのまま）。
数詞は助数詞に合わせて読む（3分→さんぷん、9月17日→くがつじゅうしちにち、4時→よじ、28℃→にじゅうはちど、2人→ふたり、
30%→さんじゅっパーセント）。出演者名は辞書が弱いので、構成表で LLM に読み（`kana`）を書かせ、それを使う。読みの無い名前は
漢字のまま残す。`AITV_NO_YOMI=1` で変換を止められる。index の `prompt` には実際に送った（かなの）文が残る。

**再開**: 再起動やクラッシュで途中になった番組は、index にある番組 ID から台本を読み直し、残りのクリップだけを
続けてレンダリングする（数時間ぶんの GPU を捨てない）。

**素材（`internal/sources`）**: 素材が要る番組（news / weather / variety）は架空の内容で埋めない。
取得できなければその枠は今回は飛ばす（60 秒待って次の枠へ）。取得結果は 20〜60 分キャッシュ、
オフラインでも落ちない（`AITV_OFFLINE=1` で取得自体を止める、地域は `AITV_JMA_AREA`）。
各クリップの `index.json` には `sources`（使った見出し）と `programme_id` / `slot` / `section` が残る。

## 24 時間運用と編成

```powershell
.\scripts\run_station.ps1            # ComfyUI（未起動なら）+ プレイヤー + HLS + 制作ループ（無限）を常駐起動
.\scripts\run_station.ps1 -Restart   # 作り直し（制作中の番組は途中で止まるが、レンダリング済みのクリップは残る）
.\scripts\run_station.ps1 -Stop
.\scripts\run_station.ps1 -NoTurbo   # turbo LoRA を使わない（LoRA 適用時に ComfyUI が OOM で落ちる場合、docs/pitfalls.md）
.\scripts\run_station.ps1 -Minutes 3 # 全番組を 3 分に（1 日の周回が約 2 倍速くなる）
.\scripts\run_station.ps1 -NoProduce # 生成なし: 既存ライブラリを流すだけ（ComfyUI も Ollama も起動しない。GPU は空く）
```

制作速度は実時間の約 1/30（640×352）〜1/60（832×480）。**1 日回して作れる新作は 45〜50 分**で、
上の 8 枠編成はそれをちょうど使い切る設計。放送局として 24 時間止めないことと、24 時間ぶんの新作が
毎日できることは別で、後者はこの GPU では不可能。そこで 1 日ぶんの編成を 1 日かけて作り、放送はそれを周回する。

### 編成（`internal/rundown`）

1. 放送は `LINEUP` の枠順に回る。各枠では、その枠向けに作られた**完成済み**（全クリップがレンダリング済み）の
   番組を頭から通しで流す。できたての番組が最優先、全部流し終えたら過去の日の番組も新しいものほど多めに再放送。
   番組の後に CM 1〜2 本 → 局 ID。
2. まだその枠の番組が 1 本も完成していなければ（起動直後や制作中）、旧ライブラリの同ジャンルの短い番組を
   1 分ほどまとめたブロックで埋める。クリップ単位でランダムに飛ばすことはしない。
3. 短い番組の選び方: まだ流していないものがあれば新しい順、無ければ直近を避けつつ新しいものほど重いランダム。
4. 出典（`sources`）の無いニュース・天気・バラエティー（実素材を使う前に作った架空のもの）は放送しない。ファイルは残る。

Web プレイヤーは HLS（`aitv/web/hls.min.js`）で同じストリームを見るので、ブラウザでも VLC でも編成は一つ。
画面のタイトル表示は放送側が書く `aitv/hls/now.json`（時刻付きのオンエア記録）と、ストリームの
program-date-time を突き合わせて出す（HLS の数秒の遅延があってもずれない）。

## 連続運転のための作り（レビューで直したもの）

数日回す前提でコードを見直し、確認できた不具合を直した。

| 症状 | 原因 | 対処 |
|---|---|---|
| 配信が止まったまま復帰しない | HLS エンコーダが死ぬと、remux 側が誰も読まない stdout パイプに書き込んだままブロックし、`remux.wait()` が永久に返らない | 壊れたら remux を kill してから待つ。エンコーダは自動で作り直す |
| 再生時刻がおかしい | `-fflags +igndts` が正しい DTS を捨て、クリップ境界以降のタイムスタンプが 1 tick 刻みに潰れる（実測 71 % のフレーム） | `+genpts` のみに。1/24 秒刻みに戻ることを ffprobe で確認 |
| 生成したクリップが消える | `index.json` を `os.replace` で置き換える際、他スレッドが開いていると Windows は PermissionError。約 400 秒かけた生成が索引に載らない | `internal/index` に集約。読み手は閉じてから parse、書き手はリトライ＋最後は上書き |
| 生成が永久に止まる | HIP がハングしても `/system_stats` は応答し続けるので、生死判定だけでは検知できない | 無反応タイムアウト（既定 20 分）で `/interrupt` と待ち行列削除。失敗が続けば ComfyUI 再起動 |
| ディスクが減り続ける | ComfyUI の生出力（1 クリップ約 1.4 MB、1 日約 200 本）を誰も消さない | 正規化してライブラリに入れた後で削除 |
| 二重起動 | Windows の SO_REUSEADDR は listen 中のポートにも bind できてしまう | Windows では無効化。ランチャも PID ファイルで単一起動を保証 |
| 停止で無関係なプロセスまで落ちる | コマンドラインの `-m aitv` 部分一致で kill していた（実際に別のシェルを巻き込んだ） | PID ファイル＋`taskkill /T` に変更 |
| ログ出力で落ちる | （Python 版）cp932 では日本語キャプションを encode できず、リダイレクト時に UnicodeEncodeError | Go 版は常に UTF-8 バイト列を書くので起きない |

`.\scripts\run_station.ps1 -Status` で稼働状況、`-Stop` で停止、`-Stop -All` で ComfyUI も停止。

## 配信（`internal/rtmp`）

局は HLS を出すだけなので、YouTube Live / Twitch / TikTok LIVE に載せるには RTMP で押し込む。`aitv rtmp`（または
`aitv station --rtmp` / `run_station.ps1 -Rtmp`）が 1 本の ffmpeg で **テロップを焼き込みつつ** 送出する:
局名バグ、「● LIVE 時刻」、番組タイトル、「セクション · キャプション · 制作 日時」、赤帯のスクロール（番組表）。
Web プレイヤーと同じ見た目を、配信先には画素として渡す。

- ストリームキー入りの URL は環境変数 `AITV_RTMP_URL` に置く（`rtmp://<サーバー>/<キー>`）。ログには伏せ字で出る。
  ffmpeg の引数には載る（ローカルのプロセス一覧からは見える）。
- `--portrait`: TikTok 向け 9:16（1080×1920、30 fps、約 4.5 Mbps）。16:9 の絵を中央に、上下は同じ絵のぼかしで埋め、
  テロップはその帯に置く。横のままなら 832×480 / 24 fps をそのまま再エンコード（約 2.5 Mbps）。
- **同期**: HLS は数秒遅れるので、ffmpeg にプレイリストを読ませず、pusher がセグメントを自分で追いかけて
  「そのセグメントを放送側がいつ流したか」（`now.json` の時刻とセグメントファイルの更新時刻）を突き合わせ、
  テロップの文面を差し替えてから ffmpeg に流し込む。クリップ境界がセグメントの途中にあるときは TS を
  キーフレームで 2 つに割って間で差し替える。デコーダは `-threads 1`（フレーム並列だと 17 フレーム先読みされ、
  前のクリップの末尾に次のタイトルが焼き付く）。
- 切れたら 5 秒後に ffmpeg を作り直し、ライブ端に再同期する。放送側のエンコーダ再起動（メディアシーケンスの巻き戻り）も同様。
- TikTok の運用上の注意: LIVE Center / LIVE Studio で「サードパーティ配信」を選ぶとサーバー URL とキーが出る。
  キーは配信セッションごと。こちらの送出が数分止まると TikTok 側がセッションを閉じるので、その時はキーを取り直す。
  AI 生成コンテンツのラベルを付ける。

```powershell
[Environment]::SetEnvironmentVariable("AITV_RTMP_URL", "rtmp://<server>/<stream key>", "User")   # 一度だけ
.\bin\aitv.exe rtmp --portrait                                # 局とは別プロセスで送出（止めても放送は続く）
.\scripts\run_station.ps1 -Restart -NoTurbo -Rtmp -Portrait   # 局と一緒に起動する場合
```

## 設計メモ

- **1 クリップ = 1 生成**。H3 は 4〜15 秒の生成が前提なので、番組は短いセグメントの連結として設計。
  同一人物の継続性は Ref2VA（参照画像＋声）で実現できる（`h3gen gen --mode r2v`）。
- **正規化**: 生成物は ffmpeg で 24fps / H.264 / AAC 48kHz に揃えて `aitv/library/` に置く。
  HLS ブロードキャスタはストリームコピーで TS 化して連結するので再エンコード不要。
- **プレイヤー**は HLS ストリームの視聴画面（hls.js、Safari はネイティブ）。テロップは `now.json`、
  ティッカーは `playlist.json`（30 秒ごと）。ストリームがまだ無い間はカラーバー表示。
- **HLS** は ffmpeg 1 プロセスに stdin から TS を流し込み続ける方式（`-re` で実時間ペース）。
  ライブラリに追加されたクリップは次のブロックで自動的に流れる（`/clips/<file>` の直接再生も残してある）。
- **実装**: 最初の版は Python（`aitv/`, `h3gen/`）で書き、動作が固まったところで Go に全面移植した
  （`cmd/aitv`, `cmd/h3gen`, `internal/*`。移植の契約は [go-port.md](go-port.md)）。Python 版は
  `archive/python/` に参照用として残してあるが、もう実行しない。ComfyUI（H3 のレンダリングエンジン）だけは
  Python のまま、HTTP/WebSocket 越しに使う。
